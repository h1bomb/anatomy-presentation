## 2. 零白屏极速加载策略

### 2.1 传统单体架构的痛点
在重度依赖 3D 渲染与复杂等轴测矢量组件的应用中，若将所有部件打包至单一脚本，体积往往极其庞大（重构前为 **21.1 MB**）。在弱网或普通网络环境下，浏览器在全量下载并解析这 21MB 代码前无法执行 DOM 绘制，造成长达 5 至 15 秒的白屏等待。

### 2.2 三级渐进式加载方案
1. **第一级：内联轻量骨架屏（< 10ms FCP）**：
   - 在 `index.html` 的 `<head>` 与 `<div id="root">` 内置完整样式的纯 CSS 骨架屏（体积小于 3KB，零外部网络往返依赖）。
   - 网页建立连接的瞬间即刻呈现 Anatomy 暗黑调色盘（`#111110`）、金色脉冲光环与刻度扫描条，彻底消灭白屏盲区。
2. **第二级：代码分割基础依赖包**：
   - `vendor-react`：React 19 核心库（约 68 KB gzip）。
   - `vendor-router`：React Router v7（约 31 KB gzip）。
   - `index`：演播核心布局与控制框架（约 25 KB gzip）。
   - **首屏初始加载总量仅 ~130 KB (gzip)**，相比优化前削减 **160 倍**。
3. **第三级：章节部件按需动态分包**：
   - 48 组官方部件在 `src/machines/figure-loader.tsx` 中通过 `React.lazy()` 懒加载注册。
   - 用户切换章节时，仅动态拉取对应章节的独立 chunk（如 `watch-*.js` 仅需 ~149 KB gzip）。
   - 加载过程中由 `<Suspense fallback={<StageSkeleton />}>` 提供局部 HUD 骨架屏，旁白与控制面板保持常态稳定，杜绝整页重绘抖动。

## 3. 确定性虚拟时钟与视频导出

为了保证离线高清视频录制（如通过 Chrome DevTools Protocol / CDP 录制 60 FPS 无掉帧 MP4 视频），系统内置双向虚拟时钟机制：
- `window.__renderFrame(chIndex, timeSec, dtMs)`：
  - 允许外部录制脚本指定精准章节索引（0..14）与时间点秒数（0..40）。
  - 同步驱动当前拍点切换、旁白卡片状态、提词字级进度及舞台机构。
  - 返回状态审计快照：`{ chapterId, beatIndex, timeSec, figure, cue }`。
- `window.__stepOfficialClock(dtMs)`：
  - 拦截并接管 `requestAnimationFrame` 与 `performance.now`，由调用方按精确时间步长推进。
  - 保证复杂齿轮啮合、逃逸轮摆动与三维空间旋转在任意算力设备上呈现 100% 逐帧可复现的渲染结果。

## 4. 全设备视口矩阵自适应系统

演播系统以 **1920 × 1080 (16:9)** 为基础画幅。为了完美适配便携式笔记本、带鱼屏显示器、投影仪及移动端设备：
- CSS 全局定义 `--stage-scale` 缩放因子：
  $$\text{scale} = \min\left(\frac{W_{\text{可用}}}{1920}, \frac{H_{\text{可用}}}{1080}\right)$$
- 舞台根容器采用 CSS 矩阵变换中心定锚：
  ```css
  .broll-viewport {
    position: absolute;
    top: 50%;
    left: 50%;
    width: 1920px;
    height: 1080px;
    transform: translate(-50%, -50%) scale(var(--stage-scale, 1));
  }
  ```
- 窗口缩放、横竖屏切换时通过无阻塞监听器实时重算 `--stage-scale`，确保画面无裁切、无滚动条、极致居中。
